# 需求包交接契约

将以下文件保存在项目工作区；允许沿用已有等效命名，但须在 project-state.md 给出路径映射、版本和确认状态。

| 文件 | 最低内容 |
|---|---|
| source-experience.md | 原始 PRD/经历及补充答复，记录来源与日期；敏感信息按用户授权范围处理 |
| opportunity-comparison.md | 业务画像、3—5 个均带消息输入/AI 回复/追问的相邻机会；每个候选写历史线索与新增假设、差异化用户任务和业务结果、业务 Skill、拟用 MCP 读取、逐项评分、推荐理由与被排除候选 |
| requirements-baseline.md | 用户确认的定位、角色、主任务与结果、对话入口与多轮任务、业务对象、MVP/非 MVP、业务 Skill/MCP 的目标验收阶段、必要的人工责任、权限、数据权威、成功标准和未知项 |
| scenario-and-acceptance.md | 对话主路径与重要异常的两轮脚本、Skill/MCP/知识/人工协作、RAG/Context/Memory 等承诺能力的对话场景 ID、前端可见结果、必要的审批或执行回执、业务通过/失败条件 |
| technology-requirements.md | 对话、业务 Skill、MCP 与其余技术方向逐项标必接/后续/仅选型/不适用；承诺项记录对话触发、介入点、影响、失败表现、待验收证据与资源限制，不预断实际接入状态 |
| project-state.md | 产物路径、版本、草案/已确认状态、用户确认原文位置、阻断项和可交接范围 |

每项结论保留来源轴：用户原文或正式材料、合理推断、待确认；新 Agent 产品设想单独标识。P03 的旧式 P03-需求基线.md 与 P04-产品与业务流程.md 可保留为细节文档，但上述标准文件或路径映射应能让开发 Skill 直接读取。P03 主用户、任务边界、必要的人工责任和 MVP 的确认只完成基线门禁；P04 新增的场景、业务结果证据及通过/失败条件还需用户审阅确认。仅当两段确认原文及对应文件版本都记录在 project-state.md，才把整个需求包标为“已确认”。
