# Agent 项目面试追问清单

本清单用于项目面试，不包含个人自我介绍或候选人反问。项目叙事、项目问答或项目面试模拟按本次请求的范围使用；完整项目问答须逐项检查清单。以实际业务、本人职责、代码、测试、Trace 和证据台账为依据，追问应结合具体场景、实现机制、取舍、效果和局限，避免套用抽象定义。

## 使用方法

1. 按检查项 ID 核对每项与项目的相关性、技术接入状态和可用证据。实战技术问答只覆盖已接入或局部实现且可核对的能力；未接入、仅选型或与项目无关的项目实战题不生成。将每项记录为 `已覆盖 / 部分覆盖 / 不适用 / 待核实`，标注证据和原因；相关项目问题不得因证据不足被悄悄漏掉。
2. 对适用项设计问题及项目化回答。对技术点沿用 P14D 的四问，并从下方选取适合该项目的具体追问；涉及多个独立故障、指标或决策时分别作答。每个问题关联证据位置及环境，并清楚区分真实经历、已验证行为、尚待验证的处理思路。
3. 没有生产环境、真实故障或实测指标时明确说明现状；可以在相关已接入技术的回答中附带标明假设的应对思路或拟定测量方法，但不得称为已发生、已部署或已验证。未接入功能的方案留在缺口记录，不充作实战题。数值须有分子、分母、样本、时间范围和测量方法。
4. 用户只请求部分主题或一批题时，检查该范围并保留其余待处理；完整问答完成前，确认每项清单都有状态，所有适用且有证据的追问已覆盖，缺口和不适用项可追溯。

## 项目背景、业务和复盘

- B01：选择一个本人实际参与的 Agent 项目：业务背景、目标用户、具体任务、解决的问题、本人职责和结果是什么？
- B02：为什么业务场景需要 Agent？分别比较固定 Workflow、传统后端或规则方案，说明模型判断、代码控制、人工决策及适用边界。
- B03：上线或试用前后的业务指标如何定义、采集和变化？未上线或未测量时如实说明，区分合成测试与真实业务效果。
- B04：如果重新做一次，哪些产品、架构、实现或验证环节会改进，理由和成本是什么？
- B05：项目最困难的真实问题是什么？按现象、发现方式、排查链路、根因、架构或实现调整、验证结果和复盘说明；没有实际案例时明确无案例。
- B06：任务成功率如何定义、统计和解释？实际数值、工具调用失败率、最容易失败的任务类型、原因和优化措施分别是什么？缺数据时说明尚未统计及可行的测量方案。

## Agent 执行、工具与恢复

- T01：用一个复杂任务说明触发、计划、连续工具调用、条件分支、中间结果、最终结果以及每一步的证据；哪些决定由模型给出，哪些由业务代码、规则或人员控制？
- T02：执行中发现原计划不合理时，如何判断、调整、重新规划或升级人工？如何控制调用次数、执行时间、终止条件和重复调用，防止陷入循环？
- T03：模型选错工具、参数格式错误或格式正确但业务含义错误时，分别如何识别和处理？调用不存在的工具如何兜底？如何在服务端限制越权工具调用？
- T04：多工具任务中某一步失败时，哪些已成功结果和状态保留？哪些错误可重试、哪些不可重试，依据是什么？何时超时、停止或人工接管？
- T05：重试、恢复或断点续跑遇到已经产生的外部副作用时，如何防止重复执行？工具或业务接口如何做幂等、去重、补偿或回滚？以实际实现为准说明边界。
- T06：每一步执行结果如何校验、追溯来源并决定是否继续？前一步成功、后续步骤失败时如何恢复？哪些关键步骤必须由业务代码控制？

## 框架、RAG、上下文与记忆

- K01：实际使用了什么 Agent 框架或自研方案？为什么选择，它解决了哪些问题，有哪些局限？哪些能力由团队补充，框架执行逻辑不满足业务时如何扩展？
- K02：检索结果正确但模型回答错误时，如何区分检索、上下文组装、生成和校验环节的问题，并如何处理？上下文过长、关键内容被截断时如何识别及应对？
- K03：新旧知识文档冲突时，如何依据来源、版本、生效时间和权限处理？上下文压缩与结构化检索分别适合解决什么问题，各自的优势与局限是什么？
- K04：哪些场景应调用业务接口获取实时或结构化数据，哪些场景适合基于知识生成回答？调用失败或数据不足时如何处理？
- K05：多轮对话、历史筛选、压缩、会话记忆和长期记忆如何管理？哪些信息值得长期保存，依据和更新、删除规则是什么？如何隔离不同用户、租户或项目的记忆，避免串数据？

## 多 Agent、性能与工程化

- O01：是否使用多 Agent？为什么采用或没有采用，和单 Agent 相比解决了什么问题？各角色怎样传递任务、上下文与结果，怎样防止重复工作或相互调用？
- O02：引入多 Agent 后如何比较成本、延迟和任务成功率？区分实际测量、设计预期和未测量项，说明比较条件。
- O03：如果有真实的线上延迟升高、成本增加或其他事故，如何发现、定位、处理及复盘？没有生产经历时不编造事故。单任务的时间和模型调用次数如何限制？
- O04：实际做过哪些性能或成本优化？说明前后指标、样本和测量条件；若没有测量，明确待测。项目如何进行多租户隔离、模型路由与成本控制，实际边界是什么？
- O05：哪些能力由团队自研、复用或购买？为什么这样划分，框架和平台各承担什么职责？

## 评估、发布与决策

- E01：如何判断 Agent 版本升级后业务是否变好？评测集从哪些环境和数据构建，覆盖哪些任务及异常，如何避免把合成测试说成生产评测？
- E02：如何在相同数据和条件下比较不同模型、Prompt、工具描述及版本？用哪些业务、质量、延迟和成本指标，如何分析失败样本？
- E03：上线后效果下降时如何发现、定位并回滚？说明实际具备的监测、版本、发布和恢复机制及尚未实现的环节。
- E04：业务落地最大的限制是什么，哪些工程措施能缓解，哪些问题仍需人工或业务决策？依据什么业务效果、风险、成本和验证结果决定继续投入 Agent，或调整为固定流程、规则和传统工程方案？
