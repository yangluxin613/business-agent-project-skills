# 对外事实锁定与项目叙事（P14A—P14B）

用户可以只请求项目介绍或叙事，但写作前仍需核对相关事实。完整技术开发不是生成叙事的前提；未开发部分用设计或规划措辞。对外材料不得把新构建的 Agent 项目自动放入用户过去的雇主经历。

## P14A：陈述级证据

读取用户原始经历、确认的需求、当前代码、配置、测试、浏览器/模型/外部接口记录及 P13 技术状态。每条拟使用的事实建立陈述 ID，记录原句、来源种类、精确位置、日期/环境、准确措辞、不可扩大的说法及 `可用 / 需限定 / 待确认 / 不可用`。特别核实雇主/岗位/时间/本人职责、原项目与新项目的关系、客户上线范围、真实系统/Mock/合成数据、技术是否实际接入，以及成果数字的分子/分母/样本/时段。用户陈述可标“用户陈述”，不伪装成系统测量；AI 旧结论不是原始证据。

资料缺失时先完成能核对的部分，只问会影响项目身份或重要陈述的问题。产物为可对外陈述台账和禁用/待确认清单。只有台账“可用/需限定”的句子进入 P14B—F。

## P14B：面向不同读者的叙事

需要准备项目面试追问或完整项目面试时，读取[项目面试追问清单](project-interview-questions.md)，结合实际项目核对业务背景、选型、指标、故障和改进问题。仅请求项目介绍时，按本次要求处理。

先业务背景、用户、触发、旧路径与痛点，再完整业务闭环、Agent/规则/人工分工、架构、本人具体贡献、取舍、可核验结果和局限。给业务/架构评审版、约 60 秒口述版、约 3 分钟技术版和追问地图。每个事实句可回到 P14A 陈述 ID；数值只用核准口径。面试追问覆盖为何 Agent、复杂异常、责任边界、技术成本、部署与验收范围。

阶段验收：逐句核对 P14A，业务结果、工程验证和设计目标分开写；没有证据的“显著提升、客户上线、生产级”改为准确描述。用户若只要求一个长度的版本，只交付该版本，不强制生成全部材料。
