# 技术面试目录、问答与简历（P14C—P14E）

面向 Agent 开发工程师岗位，项目实战技术点只从**已接入或局部实现且可核对**的能力选择。仅选型/未接入方向可谈设计判断，但不写成落地经验；不要把“感知能力”等抽象标签冒充具体技术。

## P14C：技术点目录

按项目 P05 技术覆盖、P13 现状、代码和 P14A 证据台账筛选具体机制，例如 Function Calling 参数校验、RAG 混合召回、上下文投影、检查点恢复。每项列业务场景、前端入口或后台证据、核心机制、代码文件与函数/类、实现深度、失败路径、取舍和对应问答章节。去重并标“待审”项；无法核实代码落点的项不能进入实战问答。目录章节按项目实际技术自然分组，不凑固定数量。

## P14D：分批详细问答

生成项目面试问答时，读取[项目面试追问清单](project-interview-questions.md)，按本次请求范围盘点适用题目、证据和缺口；完整问答须逐项对账。清单仅用于项目面试，未接入或无依据的项目实战题不能写成已落地经历。

一次处理少量技术点，保存后继续，直到目录覆盖完。每项回答四问：技术是什么（输入输出与相近技术区别）；项目如何实现（用户触发、数据、权限、状态、代码与 Trace、失败路径）；为何选它（至少一个替代方案、质量/成本/延迟/复杂度/风险）；业务为何需要及已证实价值。给一个实际场景和可追问的局限。局部实现准确划边界，不编造代码符号、行号或指标。每批核对四问齐全、来源准确，全部完成再标 P14D 通过。

## P14E：Markdown 简历

核对用户简历中的姓名、教育、任职、时间、职责与当前项目事实。核心技术写清 `技术名 → 掌握/实践深度 → 能做什么 → 落地场景`；项目条目写业务问题、本人工作、关键实现与可核验结果，每条 bullet 映射 P14A 陈述 ID。不要把新 Agent 项目自动归入旧岗位；成果数字保留统计口径，合成验收与真实业务收益分开。默认 Markdown，用户要求时再导出其他格式。最终检查日期/数字一致、信息位置和一页阅读顺序。
