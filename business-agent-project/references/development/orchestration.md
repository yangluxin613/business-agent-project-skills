# 多 Agent 与有状态编排（P10D）

先用同一批业务样例检验单 Agent 是否已足够；多 Agent 只在专门分工可带来可测质量或责任收益时接入。即使只做单 Agent，也说明 Loop、调度、观察、校验和人工升级边界。

## P10D1：角色协作与配对比较

为主角色及资料/来源等专用角色划分最小事实、工具与权限；交接用结构化输入/输出和任务 ID，不允许相互无限调用或重复工作。调度器限制轮次、Token、耗时和并发，处理条件分支、串行/安全并行、超时、重试、终止与升级。用相同冻结案例比较单/多 Agent 的行动正确性、失败、Token 和延迟；若无优势，保留简单路径并记录原因。验收角色权限、交接完整性、重复调用终止和旧路径回归。

## P10D2：检查点、队列与恢复

对长任务保存业务对象级检查点和中间结果；恢复时重验当前权限、来源、知识/Skill/模型版本，以及有副作用调用的幂等键。外部调用结果未知时先对账，不能假称无缝续接中断的模型调用。测试服务中断、重复事件和人工接管；涉及审批的场景另测来源变更后旧批准失效。把串行、并行、跨进程恢复的实际接入范围分开记录。

输出结构化交接例、配对数据、恢复演练、前端业务结果、验收卡和 P10D 实施记录。
