# 单场景业务增量（P09）

每次只接入**一个**与 P08 共享业务对象、又增加实际业务价值的场景。进入前检查 P08 的主路径和适用的权限/状态门禁是否通过；未通过则先修复，或只输出标记依赖的场景草案。场景来自所选行业的真实用户任务，不机械套用医疗或工单示例。

先给场景卡：触发、角色、用户操作、输入及权威来源、Agent/规则/人工分工、可核实的业务结果、失败兜底、受影响旧流程、可见页面结果；有业务写入时再写状态变化和回执。把新增功能和适用的权限矩阵、状态机对照。只读场景核对来源变更后的解释是否更新、引用是否仍有效、用户纠错能否生效；行动场景还要明确取消、移交后旧批准是否失效，重复事件是否会生成两次行动，历史是否保留。

为本场景单独开验收卡，先固定主路径、异常/越权路径与旧场景回归，再改页面、API 和持久化。执行测试和浏览器操作，保存实际结果；失败修复复测。只有该场景验收通过，才把它加入“已完成场景”并进入依赖它的下一个场景。更新需求、接口、状态、运行说明与技术覆盖表；不要把下一批只设计的场景写成已接入。产物为场景规格、代码、验收卡和 P09 增量记录。
