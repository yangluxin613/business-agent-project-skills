# 评估、观测与逐项验收（P12—P13）

可以在任意开发阶段做局部评估；P13 是当前承诺范围的最终审计，不会把目录中仅设计/选型的能力说成已实现。从已有代码中途进入时先核对原始测试与运行轨迹，不能把先前 AI 报告当作测试输出。

## P12A：冻结 Benchmark 和配对评估

按业务任务建立正常、边界、对抗、长上下文、多轮、工具失败、来源变化和权限越界样例，记录 gold 来源、业务复核者、版本/哈希。离线指标包括意图/任务、工具选择/参数、状态、知识 Recall@K/MRR、引用、忠实/完整/幻觉、安全、成本和延迟；只用适合当前业务的指标计算，不伪造无法判断的专业正确率。配对比较固定样例、模型配置与提示词版本，报告请求数、失败尝试、Token、耗时、样本量和不确定性。无真实用户流量时，采纳、满意度、业务转化仅定义在线观测口径，不填生产 KPI。

## P12B：Trace、看板与条件优化

关联用户请求、LLM、RAG、Tool、MCP、多 Agent、状态和 Memory 的 Trace；设计性能、成本、工具失败、人工接管、业务结果与异常告警看板。用实际请求演示故障定位。若评估发现可复现问题或成本瓶颈，先定修复范围，再用相同样例/配置复测及旧流程回归；未发现可靠瓶颈则如实记录方法和样本限制，不制造问题。

## P13A：技术状态与证据审计

读项目 `technology-coverage.md` 与[默认技术目录](technology-catalog.md)，逐 ID 核对代码、配置、运行和测试。状态用 `已接入 / 局部 / 仅选型 / 未接入 / 定义待确认`，注明实际环境。对每项承诺接入的 AI 技术写业务功能、对话场景 ID、用户消息/追问、回复或业务动作变化、失败路径、代码/配置位置、同一请求的后台 Trace/测试、证据时间和限制；缺对话或后台证据时不得仅凭技术目录标已接入。KV Cache、恢复等后台能力用对话请求的指标或恢复演练证明，可以没有独立页面按钮；不能为满足“前端映射”编造 UI。

## P13B：业务操作手册与最终回归

用户可见功能写成“进入页面→点/输入什么→看到什么→异常怎么办”的可执行步骤。完成当前改动所需的自动化、真实浏览器闭环和实际模型/MCP/外部接口调用；资源不足时明确待验收。逐项对账所有承诺范围与验收卡，列未通过阻断项和后续阶段。只有当前承诺范围达到预先确定的标准，才标为当前版本完成。输出 P12 报告、P13 技术证据清单、操作手册与验收结果。
