# 项目状态与阶段验收契约

仅在需要写入项目产物、恢复进度或判断阶段门禁时读取本文件。它描述**项目工作区内的动态文件**，不把用户项目状态写回 Skill 目录。尊重用户已有目录；新项目可使用 `agent-project/`。无文件工具时，在对话中输出同样字段的可复制 Markdown，并把运行验证记为待验收。

## 最少项目文件

- `source-experience.md`：用户原始经历、明确补充与日期；保留原文和来源。
- `project-state.md`：本次请求范围、当前工作单元、已确认基线、依赖、产物、阻断与下一步。
- `technology-coverage.md`：技术点 ID、业务功能、为什么用、怎么用、阶段、接入状态、证据与边界。
- `evidence-ledger.md`：对外陈述与原始来源的映射。事实来源、实现/验证状态、运行环境分列。
- `acceptance/<unit-id>.md`：已承诺实施的每个开发子单元一张验收卡。可以合并存放，但字段不可丢。

在 `project-state.md` 中记录 `项目标识 / 工作区 / 本次用户请求原文或精确范围 / 当前单元 / 单元状态 / 基线版本 / 直接前置条件及证据 / 产物路径 / 阻断项 / 下一步`。单元状态用 `未开始、进行中、通过、失败、待验收`；设计草案可另标 `草案`，不能写成已确认或通过。每次改变状态都留日期和原因。用户修改需求或原始证据时，评估受影响的下游单元并重新打开其验收卡。

## 证据三轴

1. **来源**：用户陈述、正式业务文档、代码、测试输出、浏览器/工具轨迹、外部系统记录、生产指标；记录精确路径或原文位置。
2. **实现与验证**：仅设计、代码已接入、局部验证、验收通过、失败、待验收。代码存在不自动等于运行通过。
3. **环境**：合成/Mock、本地真实模型、测试/预发、客户生产。Mock 对接不自动等于真实接口联调；本地真实模型调用不自动等于生产运行。

对外陈述还需记录陈述 ID、准确措辞、数值口径、可用/需限定/待确认/不可用。用户提供的就业或上线信息可标为“用户陈述”，不要伪装成系统实测。未知的客户、指标、专业结论不补造。

## 验收卡

开发前填写：`单元 ID / 承诺范围 / 依赖版本 / 实现环境 / 主路径 / 关键失败与权限路径 / 禁止副作用 / 受影响旧流程 / 预期结果 / 通过条件`。业务 gold 在实现前冻结，记录版本；因真实需求变化而修改时记录原因、旧版与新版差异，并重跑相关验收。

执行后填写：`代码或配置版本（Git SHA；无 Git 时用文件路径和摘要） / 测试时间 / 命令或前端操作 / 输入数据 / 模型与外部系统运行模式 / 预期与实际 / 原始输出、截图或 Trace 路径 / 失败原因 / 修复内容 / 复测结果 / 结论 / 阻断的下游单元`。凭证和敏感原文不能进入日志或验收卡。

结论只能是：

- **通过**：本次承诺范围内的必要检查已实际执行且符合预设标准；关键失败路径和受影响旧流程已回归。
- **失败**：执行过但未达标准。修复后复测，保留原失败记录。
- **待验收**：缺运行工具、模型密钥、外部接口、GPU、真实业务专家或其他必要条件；写清缺什么和如何补验。设计草案可以交付，但依赖实际通过的后续单元仍被阻断。

只有直接依赖的验收卡为“通过”，下游才能把该能力当作已完成前提。独立工作可继续。可用 `依赖 A → B` 表示阻断；不要因一个可选或未承诺实际接入的方向待验收而阻断已承诺范围。需求、代码或配置变更影响已通过结论时，重开受影响验收卡再回归。

## 简短状态转移例

`P08 主闭环` 的验收卡起初是“进行中”；浏览器主路径成功，但越权操作没有被拒绝时改为“失败”，`P09 新场景` 被阻断。修复权限并重跑越权路径、主路径和受影响旧流程后，记录新代码版本与结果，才改为“通过”。若尚无浏览器环境，则记“待验收”；可以继续撰写独立的知识目录设计，但不能声称 P08 已验收或以 P08 通过为前提完成 P09。
