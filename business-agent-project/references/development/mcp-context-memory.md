# MCP、上下文工程与 Memory（P10C）

三者可以分别被请求，也必须分别验收。先读取现有模型/检索链路的权限与来源契约；缺相应前置时只做可独立部分或带依赖的设计，不宣称整段完成。

## P10C1：MCP 工具与资源

只发布业务真正需要的 Tool、Resource、Prompt，定义注册、版本、健康、发现、超时、审计、失败和下线。用对话中的业务问题触发授权 MCP 读取，让回复使用返回事实并显示可核对的来源；工具失败、越权或结果未知时在同一对话中说明并转人工或重试核对。用户身份、组织、角色、任务对象、知识版本和有效期由可信宿主绑定；工具返回后宿主再次校验。写操作还受已确认业务规则要求的授权/人工审核与幂等门禁。区分本地 stdio、内部网络服务、私有部署与仅设计形态。测试正常调用、额外参数、越权、过期授权、工具失败与旧流程回归；提供同一请求的协议调用轨迹，不能只凭页面文字证明 MCP 路径运行。

## P10C2：Context Engineering

定义系统、用户、任务、业务、工具、知识、历史与记忆的优先级和可用范围。选一段真实可复验的多轮业务对话，记录每轮装入的当前消息、任务状态、授权历史、知识引用和经允许读取的记忆；追问必须保留必要条件并排除无关或越权内容。非可信原文只作数据；冲突时保留来源并让可信规则优先。长文按章节/块抽取与摘要，保留引用位置和关键条件，设置窗口与 Token 预算；超预算时在对话中显式追问、说明裁剪限制或拒答。测试注入文本、冲突来源、关键条件跨块、长文超限与成本/延迟；对话中的回复变化与后台上下文组成/压缩 Trace 都要可核对。

## P10C3：可纠错 Memory

分会话、任务、个人偏好、长期语义与组织级记忆；逐类定义谁可写、从什么已确认事实写、何时读、权限过滤、有效期、版本冲突、人工修正、删除与来源失效。选择业务人员在对话中确认的一项可记事实，记录写入来源；用下一轮或下一次会话的真实问题触发读取，检查它如何影响回复，再从页面纠错或删除并复问，确认旧记忆不再生效。当前权威事实高于历史记忆；无权、过期、冲突记忆应在对话中忽略或提示核实。测试跨会话读取、跨组织隔离、纠错后重读、删除/失效和审计；语义长期记忆需证明检索与回复的关联，而非静态字段。

分别输出代码/配置、用户操作、运行轨迹、验收卡与 P10C 实施记录。任何一项未通过时只标该项失败/待验收，不把另外两项一起否定或一起宣称完成。
