# 技术覆盖、状态与接口规格（P05—P06）

读取已确认的业务需求包及项目技术要求。若仅有草案，只可产出标假设的架构草案，不能把它作为已冻结开发依据。P05 技术映射先于 P06 可开发规格；P04 业务语义是约束。

## P05：逐项技术架构与分期

读取 [默认技术目录](technology-catalog.md)以及用户自带技术要求，建立项目 `technology-coverage.md`。逐项写 `技术 ID → 业务功能 → 为什么用 → 怎么用 → 边界 → MVP/后续/只选型 → 验收方式 → 当前状态`。对承诺接入的 AI 技术再标 `对话场景 ID → 触发消息/追问 → 介入点 → 回复/业务动作影响 → 失败/越权路径 → 前端表现 → 后台 Trace/测试`；缓存、推理服务等后台能力可关联同一对话请求的指标，不需要伪造独立页面交互。用户原技术要求每个独立方向都要对应行；不要用“RAG 已覆盖”替代解析、Embedding、权限过滤、召回、重排、引用等子项。

按业务价值与设备/接口资源选择单/多 Agent、Skill、记忆、RAG、MCP、推理和部署路径。给架构图、技术选型表、性能/成本/稳定性权衡、MVP→可用→生产→平台路线图；每阶段列目标、用户价值、技术能力、依赖、风险与验收。vLLM/TGI/Triton 比较后可只选择一种或远程 API；“比较过”不等于“部署过”。未定义的内部编码保留待确认。产物 `P05-技术覆盖与架构.md`。完成条件：原始技术方向可逐项对账，实施和选型状态不混淆；P04 的主业务任务可沿架构实际流转。

## P06：状态、界面和接口契约

定义领域对象/标识、权威来源与版本、角色/组织权限、业务结果契约，以及适用的业务状态和合法转换。分别规定输入变化、部分失败、结果未知、拒绝/接管的系统行为；涉及执行或长任务时再规定重复事件、取消/过期与回滚。对 MVP 画页面路径，列消息输入、多轮回复、适合结果形态的引用/时间线/比较/内容/行动视图、空态/错误态；需要批准时再列人工确认。每个交互映射到 P04 场景。对话状态须区分当前消息、任务历史、检索来源和可读取记忆，并定义权限/版本失效时如何重算。内部/外部 API、Skill、Tool 需要输入、输出、权限、错误码；有副作用的调用还需幂等键。未知外部接口只能写适配点和待确认项。

产物 `P06-状态与页面接口规格.md`，含业务结果契约、适用的状态图、权限矩阵、页面流程、接口契约、异常矩阵和开发依赖顺序。完成条件：业务结果、页面与 API 用同一套术语；P05 的 MVP 能力有对应接口，P07 可以直接据此构造验收例。
