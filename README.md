# Business Agent Project Skill

一个面向业务 Agent 项目的 Skill，包含**需求、开发、面试**三种模式。你可以提供过往业务经历或 PRD，寻找适合自己的 Agent 项目；也可以从已经确认的需求或现有代码开始，直接进入开发或项目面试准备。

| 模式 | 适合什么情况 | 可以得到什么 |
|---|---|---|
| 需求 | 有业务经历，还没有确定 Agent 项目方向 | 候选项目、需求基线、使用场景和验收条件 |
| 开发 | 已经确认项目方向、使用场景和验收条件 | 架构、可操作的项目、阶段测试记录和技术状态 |
| 面试 | 已经有项目代码，想准备项目面试 | 项目介绍、技术问答和 Markdown 简历等材料 |

## 安装与使用

下载仓库后，在支持自定义 Skill 的 AI Agent 工具中，按照该工具的方式导入 [`business-agent-project/`](business-agent-project/) **整个目录**。请保留 `SKILL.md` 和 `references/` 的相对目录结构，单独复制主指令文件会丢失各模式的细则。

不同工具的安装位置和调用方式可能不同。导入后，在对话中用自然语言说明要使用 `business-agent-project` 的哪种模式，并提供相应资料。如果工具不支持导入 Skill，可以提供主指令和相关参考文件，要求 AI 先读取主指令，再根据任务读取相应文件。

### 需求模式：寻找项目方向

准备一份过去参与的业务 PRD、项目说明，或自己整理的业务经历，尽量说明业务用户、主要工作流程和本人职责。也可以提供希望学习的技术方向、可用数据与接口等约束。没有完整 PRD 时，先提供已有信息即可。

```text
请使用 business-agent-project 的需求模式。我会提供过往业务经历和本人职责，请先梳理业务背景，再提出 3—5 个用户任务和业务结果不同的对话式 Agent 候选。区分原文事实与新增假设，说明每个候选服务谁、解决什么问题、需要哪些资料。先停在候选比较，等我选择方向。
```

比较候选并选择方向后，请 AI 整理项目定位、核心任务和首期范围。**分别审阅确认项目基线，以及使用场景和验收条件**，再进入开发。需求阶段提出的技术落点属于规划，具体接入情况以后续开发和验证为准。

### 开发模式：分阶段实现与验收

提供已经确认的需求基线、使用场景、验收条件，以及现有代码、数据和接口情况。可以先让 AI 检查资料是否完整，再整理架构和技术覆盖：

```text
请使用 business-agent-project 的开发模式。先核对已经确认的需求、使用场景和验收条件；如果缺少关键决定，标出来。资料足够后，先整理架构和技术覆盖，说明主要业务任务如何在页面完成、各项技术用在哪里，以及如何验证。完成后先停下，等我检查。
```

确认方案后，先完成一个可操作的业务闭环，再按业务需要分阶段接入技术。每个开发单元都需要明确验收条件，完成后执行测试并记录结果；失败后修复和复测，再推进依赖它的工作。没有真实数据或接口时，可以先使用明确标记的模拟资料，后续再接入并验证。

Skill 可以协助规划和实现，项目仍需要你通过多轮 vibe coding 亲自试用、反馈问题并复测。启动说明、前端操作步骤和技术状态表可以帮助你检查项目实际完成到哪一步。

### 面试模式：准备项目面试

提供项目代码、本人实际职责、测试和运行记录，以及可以公开的业务结果。面试模式围绕**项目面试**工作：先核对事实，再整理项目介绍、技术点和项目面试问答。它不会把没有证据的功能、上线或收益写成已经发生的经历。

```text
请使用 business-agent-project 的面试模式。先核对我的实际职责、项目代码、测试和运行记录，再整理项目事实与项目介绍。然后基于已接入或局部实现且可核对的能力，整理技术点和项目面试问答，说明实现机制、代码位置、技术取舍和业务价值。缺少证据的内容请标记待确认。
```

面试追问可以覆盖业务背景、工具调用、故障处理、RAG、上下文、记忆、多 Agent、评估和成本等方面；具体问题以项目实际实现和可用证据为准。你可以继续要求生成 Markdown 简历，再结合代码和测试记录核对、练习。

### 从头走完三个模式

也可以告诉 AI：“使用 business-agent-project，按需求、开发、面试完成整个项目。”过程中仍需分别确认需求基线和场景验收；开发时按阶段测试，并通过多轮 vibe coding 调整。已有项目可以从当前阶段进入，不必重新开始。
